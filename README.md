# 人性阴暗面/情绪/随机性放大

SillyTavern 独立前端扩展 · v1.1.1。让角色有自己的脾气、私心和有来由的意外反应。初次安装就开**烈性**。没有外部依赖，无需额外 API，不安装 Lin 也可以使用。已有的预设、世界书、预填充助手、显示正则和油猴脚本都不用动。

## 安装

1. 在**运行酒馆服务端的设备**上解压 ZIP。把完整的 `human-temper` 目录放入 `SillyTavern/data/default-user/extensions/`。多用户酒馆把 `default-user` 换成当前用户名。最终应看到 `extensions/human-temper/manifest.json`，不要多套一层文件夹。
2. 刷新酒馆页面，打开「扩展」里的 **人性阴暗面/情绪/随机性放大**。使用「聊天补全 / Chat Completion」连接。它不走文本补全的字符串接口。
3. 正常聊天即可。手机只作为网页客户端时，在酒馆主机上解压后刷新手机页面；ZIP 不用导入预设、正则或酒馆助手。若自己托管为 Git 仓库，将目录**里面**的文件放在仓库根目录，即可使用 ST 的「安装扩展」网址入口。

从 v1.0.0 / v1.1.0 升级：用包内 `human-temper` 覆盖原插件目录并刷新，不要另装第二份。原有设置和聊天手记沿用；旧配置若缺少「user 参与便利度」，按 50 读取。已有正文保持原样，新约束在后续生成或重新生成时生效。

## 第一次试玩

找个自尊心很强、但一向礼貌的角色，告诉他：“我没等你，先跟别人走了。对不起。”他可能仍然给你留饭，却最后一个才来桌边；可能承认自己不讲理，依旧不肯同行；也可能坦然接受。这些不是脚本台词。抽签决定当下的一股劲，角色卡、具体场景与模型决定怎么写。角色可以违背剧情里用户的愿望，不能代写用户反应；明确标为戏外的改稿请求优先。

| 滑块 | 烈性（默认） | 均衡 | 调的是什么 |
| --- | ---: | ---: | --- |
| 情绪烈度 | 100 | 82 | 新情绪的出现权重、分量和余波。拉到最高时允许情绪压倒利害判断、明知不划算仍反口。 |
| 阴暗面放大 | 100 | 75 | 记仇、嫉妒、护面子、自保等相对权重。0 停止这组动机；不禁止角色自然生气。 |
| 行为出格度 | 100 | 75 | 有来由的意外话头、小动作，以及偏离对方期待的自主选择；最高值也须符合情境与人设。 |
| 生活插曲 | 25 | 65 | 周围动静、时段变化、小便利、琐事耽搁。想让世界更吵才上调。 |
| user 参与便利度 | 保留手动值，初始 50 | 保留手动值 | 既有生活插曲、独立事务的入口是否容易发现和介入；不调事件次数。 |

前四项是**叙事权重**，不是次数百分比，更不是真实世界统计。烈性时也可能出现喜悦、笨拙的善意、害怕、提不起劲或留白。关闭「自主目标」会移除独立事务这组抽签；关闭「跨回合情绪与分支记忆」后仍可单轮抽签，也不会读写这套手记。

## 出乎意料与不迎合

出格度增加偏离预期的反应，不放宽情境和人物边界。意外话头、转题或分心应能由当前事务、已有兴趣/情绪或现场合理刺激引出；不靠无依据的精细观察、新编癖好或往事制造奇怪感。来由可以不说破，不必提前专门铺垫。抽中的方向不合此刻时，模型可略过它，继续当前事务。

启用「自主目标」时，角色优先按自身动机决定回应，不默认追求 user 满意。可以拒绝、暂不和解或继续自己的事，也保留真心关心与合作；不固定唱反调，不要求拒绝后补上道歉或示好。正在生气时工作、被别的细节逗笑等反差仍可出现，短暂的反应变化不等于原有情绪消失。剧情中不迎合，不影响戏外编辑要求或用户对自己言行的决定权。

## user 参与便利度

手动滑块控制**介入门槛**，数值越高越方便加入，不会自动随着回合数调整。它只为本轮已经抽中的生活插曲、独立事务补充参与方式，不新增事件，不改变抽签权重、情绪余波或原条目，也不把题外话、小动作扩写成支线。

| 数值 | 参与方式 |
| --- | --- |
| 0 | 不额外铺入口；user 主动介入时仍按现场条件和角色意愿回应。 |
| 1–33 | 入口较含蓄，通常需要自己留意、询问或找到时机。 |
| 34–66 | 条件合适时自然露出机会，仍留一些需要主动接近的空间。 |
| 67–100 | 条件合适时更容易看见、顺手加入，减少额外询问或等待。 |

**100 也不等于每件事都能加入，更不等于必须加入。**没有合理入口、角色想独处或已经拒绝时，保留原有边界；不凭空创造巧合或泄露角色不知道的信息。user 可参与、旁观、拒绝或离开。参与可以影响过程；不参与时，角色或环境仍能推动事件发展和收束，不会停下来等 user 解决、决定或配合，也不会反复邀请。

这项数值表达给模型的便利度偏好，不是参与概率或强制结果。切换「烈性」「均衡」保留手动值；「复制当前配置」包含该项。修改后从下一次生成生效，续写保持原事件，按当前设置调整后续呈现，不改写已保存的正文。

## 它怎样做决定

- 用浏览器的 `crypto.getRandomValues` 在本地抽签。参考当前发言角色的性格/描述，以及当前分支最近四条非系统对话的可见文字。自尊、比较、失约、时间、场所等是中英文线索，不等于完整理解整张角色卡。卡中明确写死的底线优先。遇到已有失信和利益/约定线索才开放少量严重失约选项。
- 每轮最多选一个落点，另可抽一个**表达方式**。同一股难过，有人直说，有人照常忙自己的事。模型只收到选中的方向，不会看到候选列表、概率或范例台词；本轮可以留白。角色可以前后矛盾，不要求当场自我解释。
- 烈性档抽中强情绪后，通常还有 **3–6 次该角色发言**的余波。续写同一条不消耗次数；群聊里别人发言也不消耗。余波会换表达角度，不要求每次重复同一个动作。用户道歉不会触发自动和解。若角色在正文中明确表示已平复，一些常见措辞可提前结束；也可手动结束。没有承诺能识别所有表达。
- 只给 ST 已组装的聊天补全请求前部增加一条短 `system` 说明，不调整 token、思考、温度、工具、渠道、消息末尾或用户内容。默认适用所有聊天模型，以兼容自定义别名；可改成仅 Gemini 4 Argon / Carbon / Hydrogen（另识别 `hydrgon` 拼写）。不会替你更改或补写实际模型 ID。

## 分支、长期记忆与手动校正

「查看本轮抽签和分支手记」默认折叠，避免剧透。**角色私下的一股气、正文里的字面线索、已经确认的事实，分开保存。**强烈情绪可以当作尚未流露的个人状态持续，但不会自动把“没帮忙”“发生背叛”等写成既成事实。关键词命中仅供核对，含否定、反语或他人对白时尤其需要人判断。可见文字过滤常见思考/HTML 注释，不模拟每套显示正则。

- 要保留真正发生的事，在那条回复选择连续的 2–72 个正文字符，点「钉住原句」。每轮最多带入当前分支、当前角色最近三条钉住的原句。私下线索不跨群聊角色；不依赖世界书。记录保存在当前聊天元数据中，每个聊天最多 180 条，优先保留钉住的条目。设置随酒馆保存。
- 新生成一个 swipe 候选时重新抽样。从旧候选切回来会恢复对应记录。改动或删除前文后，不再沿用旧分支的效果；重新生成不继承被丢弃的答案。继续写当前消息默认沿用本条落点。如果服务端对整段续写作了大幅重写，无法确认前缀时宁可不合并旧记忆。
- 模型忽略了落点，想让它再试一次？在聊天末条回复的手记点「下次重抽沿用这次落点」，再手动滑动**生成一个新候选**或点重新生成。锁定只用一次，点击锁定不会自行发起模型请求。切换聊天、修改设置或改走新的普通回合会取消锁定。
- 停止、空回、仅有隐藏思考、可识别的接口拒答、工具/结构化回复不会当成进行过的剧情。角色说“我不想帮你”属于剧情。戏外请求可用 `OOC:` 或 `【戏外】` 开头。干跑、后台 quiet、代写用户和一次多候选 `n > 1` 跳过。

## 兼容性和验证

独立加载和面板操作不使用任何 Lin 模块。v1.0.0 的验证记录包含两份 Lin 2.8.2 导出、预填充助手 v1.2.9 和 ST Google 消息转换器的 **192 个离线组合**；这是旧版记录，不计作本次重新验证。v1.1.0 保留原请求控制器和注入位置，新增测试核对四种 Gemini 别名、三个参与档位与两组事务共 24 个请求组合，确认原有消息对象、尾部承接和生成参数不变。旧助手本身的 Gemini 专项修复只匹配 Argon/Carbon；本扩展能在 Hydrogen 上提供演出提示，不会替旧助手增加 Hydrogen 预填充修复。

包内 32 项自动化测试全部通过：原 27 项覆盖抽签、情绪、配置、参与便利度、分支与面板操作；本版新增各档位的情境约束、非迎合与善意并存、混合反应不自动消气、商谈场景请求/续写和留白五项测试。保留 6000 次参与便利度高低值配对抽样，抽签结果与随机数消耗一致。与 v1.1.0 对照，抽签权重、条目标识、请求控制器、分支记忆和参与便利度逻辑未改。未连接实际付费模型，这些测试验证代码和发送的提示，不证明模型一定按要求写作。服务端拒答或网络截断不属于本扩展的控制范围。

开发者可在本目录用 Node 20+ 执行 `node --test`。运行扩展无需 Node 依赖安装或构建步骤。卸载时移除 `human-temper` 文件夹并刷新即可；不修改已有聊天正文。
